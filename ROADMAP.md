# TestAtlas Roadmap

This roadmap describes the direction of TestAtlas, not a promise of fixed delivery dates. The project will prioritize quality, review capacity, and learner value over publishing content quickly.

## Guiding rule

> Every merge should make TestAtlas better than it was yesterday.

The standards behind that rule are defined in [PROJECT_CONSTITUTION.md](PROJECT_CONSTITUTION.md).

## Phase 0 — Foundation

**Goal:** establish a clear, maintainable base before publishing learning content.

- Define project identity, mission, and long-term direction
- Publish the constitution, style guide, contribution guide, and governance model
- Establish the repository structure for learning paths, projects, labs, templates, resources, and assets
- Add a documentation site, automated checks, and a contribution workflow
- Define reusable content patterns before pages begin to multiply

## Phase 1 — Core learning paths

**Goal:** publish a reliable starting route for new and developing testers.

- Foundations of software testing
- Manual testing and test design
- API and database testing fundamentals
- A practical glossary and cross-linked reference material
- Initial templates and checklists that support the learning paths

## Phase 2 — Hands-on practice

**Goal:** help readers turn concepts into working skills.

- Runnable labs for API testing, SQL, browser automation, and CI workflows
- Exercise-based learning with setup, expected outcomes, and verification
- Cheat sheets, decision trees, and diagrams for common testing decisions
- Initial Interview Academy paths based on realistic scenarios

## Phase 3 — Real project simulations

**Goal:** teach end-to-end testing work in realistic product contexts.

- Project simulations beginning with high-value domains such as banking and e-commerce
- Requirements, user stories, acceptance criteria, test scenarios, test cases, defects, and regression coverage
- API, database, automation, and performance work connected to the same product context
- Traceability patterns that demonstrate how quality work connects across delivery stages

## Phase 4 — Advanced quality engineering

**Goal:** support engineers working beyond individual test execution.

- Maintainable automation architecture and framework guidance
- Performance and security testing foundations
- AI-assisted QA practices with clear limits and responsible-use guidance
- Quality strategy, observability, risk analysis, and QA leadership material

## Phase 5 — Community ecosystem

**Goal:** make TestAtlas sustainable through responsible open-source participation.

- Contributor recognition and a hall of fame
- Monthly challenges, bug hunts, and community-led improvements
- Translation and accessibility initiatives
- Regular content freshness reviews
- A transparent process for prioritizing issues, proposals, and roadmap changes

## How priorities are chosen

Proposed work is evaluated using the project's decision order:

1. Best Practice
2. Scalability
3. Maintainability
4. Contributor Experience
5. Learner Experience

The roadmap may change when evidence shows a better route. Architectural changes and major content patterns require documented discussion under [GOVERNANCE.md](GOVERNANCE.md).
