# Support

Where to go depending on what you need — this routes you to the right place faster than opening something in the wrong category and waiting for a redirect.

## I found an error in the content

Open a GitHub issue using the **Content Correction** template. Include the page URL or file path, what's wrong, and — if you know it — what it should say instead. See `.github/ISSUE_TEMPLATE/`.

## I found a bug in the site itself (not the content)

Broken link, build failure, a page that doesn't render correctly, search not working — open a GitHub issue using the **Bug Report** template.

## I want to propose new content — a module, a lab, a new learning path

Read [AUTHOR_GUIDE.md](AUTHOR_GUIDE.md) first. For a single module addition to an existing path, follow its workflow directly. For a new learning path, open an issue using the **Learning Path Proposal** template — see [CONTRIBUTING.md](CONTRIBUTING.md)'s "Before you start" section for why this comes before writing content, not after.

## I have a general question about using TestAtlas

Open a GitHub Discussion (if enabled on this repository) or a GitHub issue using the **Question** template. This includes "how do I navigate to X" or "is Y covered anywhere" — not everything needs to be a bug report.

## I want to report a security vulnerability in the site's code

Do not open a public issue. Follow [SECURITY.md](SECURITY.md)'s private reporting process instead.

## I experienced or witnessed a Code of Conduct violation

See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md)'s Reporting section. Contact a project maintainer directly rather than raising it in a public issue or discussion, so it can be handled with appropriate privacy.

## I want to contribute but I'm not sure where to start

Read [CONTRIBUTING.md](CONTRIBUTING.md), then [AUTHOR_GUIDE.md](AUTHOR_GUIDE.md) if you're working on curriculum content specifically. Check `docs/community/GOOD_FIRST_ISSUES.md` for a curated list of small, scoped starting points. Both main guides are written to answer "what do I do first" directly — if you finish both and still don't know where to start, that's a real gap in those documents, not something to work around silently. Open an issue describing what you were trying to do.

## I want to know what's coming next / influence the roadmap

See `COMMUNITY_ROADMAP.md` — it's the plain-language version of `ROADMAP.md`, written specifically to explain how your feedback actually shapes what gets built next.

## Response time

TestAtlas is maintained by volunteers. There's no guaranteed response time — see [GOVERNANCE.md](GOVERNANCE.md) for how decisions get made and who makes them.
